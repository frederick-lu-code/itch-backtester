# M2 walkthrough: order book

## What was added

- `include/itchbt/book/types.hpp`: `Order`, `Level`, `LevelView`, the `BookChange` record every
  operation returns, anomaly counters, and the priority-key mapping that lets bids and asks
  share one container.
- `include/itchbt/book/baseline.hpp`: `StdOrderMap` (`std::unordered_map`) and `MapLevels`
  (`std::map`).
- `include/itchbt/book/book.hpp`: `SideBook`, `Book` and `BookSet<OrderMap, Levels>` with
  `add`, `reduce`, `remove`, `replace`, `verify`, plus `apply()` overloads for each ITCH
  message.
- `include/itchbt/itch/directory.hpp`: `SymbolDirectory` and `MarketState`, built from the feed.
- `apps/book_dump.cpp`, `apps/book_check.cpp`.
- `analysis/reference_book.py`, `analysis/reconcile_close.py`, and their tests.

## How a message changes the book

`apply(books, message)` calls one `BookSet` operation. The order store finds the order by
reference (E, C, X, D and U carry no symbol or side), the operation updates the level in that
symbol's `SideBook`, and a `BookChange` comes back with the level's quantity before and after,
whether the top of book moved, and the order's sequence number. A replace returns two changes.

## Questions a reviewer might ask

- **Why is the order store global rather than per symbol?** Order references are unique across
  symbols and five of the six book messages identify an order by reference alone.
- **How do you know level totals are right?** `verify()` rebuilds every level from the order
  store and compares; `book-check --recount-every N` runs it during a real replay, and the
  Python reference book checks the same totals independently.
- **What happens on a message for an unknown order?** It is ignored and counted. `book-check`
  fails if any count is non-zero; on the reference day all are zero.
- **Why was the crossed-book invariant changed?** It was violated 642 times by the feed's own
  message ordering around reopening crosses. The write-up is in `DEBUGGING.md`.
- **Is the Python reference really independent?** It shares no code, uses plain dictionaries,
  and parses the file itself with `struct`. The two are compared through text output from a
  separate process.
